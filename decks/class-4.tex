% ───────────────────────────────────────────────────────────── 4 · what is an agent
\hue{NovaPurple}
\begin{frame}{A chat model \muted{writes}. An agent \textcolor{NovaAccent}{acts}.}
\framesubtitle{Before the standards · What is an agent?}
\vskip1mm
\begin{tcbitemize}[cardsS, raster columns=2]
  \carditem{A chat model}{Text in, text out.}{%
    It has never seen your folder and cannot run anything. \emph{You} copy code in, \emph{you}
    paste it out, \emph{you} find out whether it worked.}
  \carditem{An agent}{The same model, with hands.}{%
    It reads your files, runs commands, edits code — and sees the result of each action before
    choosing the next. It stops when the job is done, or to ask you.}

\end{tcbitemize}
\vskip3mm
{\large\color{NovaFg}\textbf{Agent \;=\; model \;+\; tools \;+\; a loop.}}
\end{frame}
\tanote{One minute, on their own experience: in Class 2 they asked Codex to show them a line of
a data file and it showed the real line — a browser chat could not have. Same model family,
different powers. "Agentic" just means: can act, not only answer.}

% ───────────────────────────────────────────────────────────── 6 · ReAct + harness
\hue{NovaPurple}
\begin{frame}{The loop has a name: \textcolor{NovaAccent}{ReAct}.}
\framesubtitle{Before the standards · Reason, act, observe}
\diagramtight[0.66\linewidth]{figures/react-loop.pdf}
\vskip1mm
\begin{tcbitemize}[cardsS, raster columns=2]
  \carditemplain{The harness}{%
    The model can only \emph{ask}. The software that runs the tool, asks your permission, feeds the
    result back and decides when to stop is the \textbf{harness} — Codex, Claude Code, Cursor.}
  \carditemplain{Why you care}{%
    Every one of them runs this same loop. Learn the loop once and the tools are interchangeable.}
\end{tcbitemize}
\vskip1mm
{\tiny\color{NovaMuted}Yao, Zhao, Yu, Du, Shafran, Narasimhan \& Cao (2022).
\emph{ReAct: Synergizing Reasoning and Acting in Language Models.} ICLR 2023 · arxiv.org/abs/2210.03629}
\end{frame}
\tanote{ReAct = "Reasoning and Acting", Yao et al. 2022 (ICLR 2023, arXiv:2210.03629): a model does
far better alternating a thought with an action and reading the result than answering in one go.
Every harness since is that loop with better plumbing. The line to land: standards 1-3 are you
configuring the harness — the rulebook it loads, the judge it runs, the stop condition of its loop.}

\hue{NovaYellow}
\begin{frame}{\code{AGENTS.md} — the file it reads first.}
\framesubtitle{Standard 1 · The rulebook}
\vskip1mm
\begin{tcbitemize}[cardsS]
  \carditem{What it is}{A README for agents}{%
    Codex reads it at the start of every session, before anything else. So do the other tools.

  \carditem{What goes in}{What it cannot guess}{%

\framesubtitle{Standard 1 · Live · 4 min}

% ───────────────────────────────────────────────────────────── 10 · standard 2
\hue{NovaAccent}
\begin{frame}{Decide what \textcolor{NovaAccent}{done} means. First.}
\framesubtitle{Standard 2 · The judge}
\vskip1mm
\begin{tcbitemize}[cardsS, raster columns=2]
  \carditemplain{Something that cannot lie}{%
    An agent stops when the work \emph{looks} done. Give it a check that answers pass or fail —
    the failing tests are your to-do list, and green is the finish line.}
  \carditemplain{Never move the goalposts}{%
    An agent that edits a test to make it pass has cheated, not finished.}
  \carditemplain{Evidence, not claims}{%
    ``All tests pass'' is a sentence. The test output is evidence. Ask for it every time.}
  \carditemplain{Green is not the end}{%
    The judge only checks what it was told to check. Then you read the diff and click the app.
    App wrong, tests green? You just found a test that should exist.}
\end{tcbitemize}
\end{frame}
\tanote{Run the red tests on stage (the command is on the Week 4 page) and open the test file
next to the spec: one test per checklist line. The "green is not the end" card is the one that
pays off today — feature 2's form field is not tested at all, so only clicking the app catches a
missing one.}

% ───────────────────────────────────────────────────────────── 11 · standard 3
\hue{NovaAccent}
\begin{frame}{Red \arr build \arr run \arr fix \arr \textcolor{NovaTeal}{green}.}
\framesubtitle{Standard 3 · The loop}
\diagram[1.0\linewidth]{figures/loop.pdf}
\vskip-1mm
\begin{tcbitemize}[cardsS]
  \carditemplain{One task per loop}{One bug, or one spec. Not ``fix everything you see''.}
  \carditemplain{Let it loop}{It runs the check, reads the failure, tries again. You read the
    result — you are not the messenger.}
  \carditemplain{Know when to stop}{Green, or twice round on the same failure. Then: new thread,
    better prompt.}
\end{tcbitemize}
\end{frame}
\tanote{The three parts are the whole lesson: a rulebook, a judge, a loop. Everything else in
agentic coding is a variation. Today the loop runs inside one Codex turn and you watch it; the
same idea one level up is a script that re-feeds the prompt until the judge passes — that is
Part II, with the team project.}

% ───────────────────────────────────────────────────────────── 12 · the loop prompt
\hue{NovaAccent}
\begin{frame}{Every good prompt has four parts.}
\framesubtitle{Standard 3 · The shape of the ask}
\vskip2mm
\begin{tcbitemize}[cardsS, raster columns=2]
  \carditem{1 · The task}{One thing.}{Name the single spec or bug you want built. Nothing else.}
  \carditem{2 · The boundary}{Where it may go.}{This branch. And never the tests.}
  \carditem{3 · The judge}{How it knows it is done.}{Run the tests after every change, and keep
    going until they pass.}
  \carditem{4 · The evidence}{What to show you.}{The final test output, and every file it touched.}
\end{tcbitemize}
\vskip4mm
\muted{The prompt written out in full is on the Week 4 page. Copy it and change two names.}
\end{frame}
\tanote{Four parts, in every loop prompt they will ever write. Get them to name the four parts
back to you before you paste it. New thread before pasting — the AGENTS.md rules from five
minutes ago are only read at the start of a thread.}

% ───────────────────────────────────────────────────────────── 13 · live kick-off
\hue{NovaTeal}
\begin{frame}{Watch it work. Then check its work.}
\framesubtitle{Class 4 · Live · Feature 2 · 13 min}
\vskip1mm
\begin{steps}
  \item \textbf{Branch.} Name it after the spec.
  \item \textbf{Red first.} See exactly what is missing before anything is written.
  \item \textbf{New thread. Paste the prompt.} Then sit on your hands.
  \item \textbf{Watch it loop.} Edit, run, read the failure, edit again.
  \item \textbf{Green. Now don't trust it.} Read the diff: did it change only what the task needed?
  \item \textbf{Click the app.} The part no test covers is the part only you can catch.
  \item \textbf{Commit, push, pull request, merge.}
\end{steps}
\end{frame}
\tanote{Let it loop for real; 2-4 rounds is normal. Narrate it as tool calls: "that's a run —
two still red — it's reading the failure — that's an edit". Commands and file names are on the
Week 4 page if you need them on screen. The two things it commonly misses on this feature:
it forgets to refresh the data files from the seed (so the tests stay green while the app crashes
on load) and it never adds the form field (nothing tests that screen). Both are the "green is not
the end" lesson — do not fix them silently, show them. If it edits a test: stop, discard, point
at the rule, re-prompt.}

% ───────────────────────────────────────────────────────────── 15 · when it goes wrong
\hue{NovaAccent}
\begin{frame}{Five things you will see.}
\framesubtitle{Class 4 · When the loop goes wrong}
\vskip1mm
\begin{steps}
  \item \textbf{It edited a test.} Discard it. Say the rule out loud. Run again.
  \item \textbf{``Done'' — but the tests are red.} Ask for the output. The output is the judge.
  \item \textbf{The same failure, three times.} Stop. Read it yourself. New thread.
  \item \textbf{It fixed three other things too.} Discard them. One task per loop.
  \item \textbf{Green, but the app is wrong.} The judge missed something. Write down what.
\end{steps}
\vskip4mm
\muted{Every line here is a candidate rule for your \code{AGENTS.md}. Keep the list.}
\end{frame}

% ───────────────────────────────────────────────────────────── 16 · retro
\hue{NovaYellow}
\begin{frame}{What did it get wrong? Write the rule.}
\framesubtitle{Class 4 · Retro · 7 min}
\vskip1mm
\begin{itemize}
  \item The worst thing the agent did today. One sentence each.
  \item Turn it into a rule: short, specific, and you could tell whether it was followed.
  \item Add it to \code{AGENTS.md}. Say \emph{why} in the commit message. Push.
  \item Three groups read theirs out.
\end{itemize}
\vskip5mm
\muted{That is how a rulebook grows — from what went wrong, one line at a time. Not from a longer
prompt.}
\end{frame}
\tanote{Collect the rules on the board; the good ones become the course's AGENTS.md for Block 2.
Expect: "refresh the data after changing the seed files", "don't edit the live data by hand",
"show me the diff before committing", "one file at a time". Reject vague ones ("be careful") —
ask "how would you know it followed this?".}
