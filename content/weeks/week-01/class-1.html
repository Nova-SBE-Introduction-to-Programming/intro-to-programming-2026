Why this course is different

You'll work the way a developer joins a company.

First

Read

You get a real codebase on day one. You ask it questions, you find your way around, you change one thing and see it work.

Then

Build

You add features, first to our app, then to your own. AI writes most of the code. You decide what to build and whether it's right.

Finally

Ship

Something deployed, with a URL, that other people can click. And you can explain every part of it.

The one rule

AI is allowed everywhere.
You can't ship what you can't explain.

Lists, loops, functions, classes — you'll meet all of them. Not to memorise them, but to read what the AI wrote, catch it when it's wrong, and tell it what you actually want.

Class 1 · Answering questions like an engineer

"Where does X happen?"

Every engineer joining a team spends week one asking this. Three ways to get the answer, from slowest to fastest — you'll use all three.

1 · Follow the click

Find the button's text in the code. Read what it calls. Read what that calls. Stop when you hit the database.

2 · Search

Search the whole project for a word from the screen. Cmd/Ctrl+Shift+F. Ugly, fast, always works.

3 · Ask the AI

"Where is a user saved?" "What happens when I click Save?" Then verify: go to the line it names and check it's true.

Demo all three live on the same question. Make the AI answer once slightly wrong (or ask a question where it guesses) so students see why step 3 ends with "verify".
Class 1 · Git, the concept

Git is save points for code.

Repo

The project

A folder git watches. Lives on your machine and on GitHub.

Commit

A save point

A snapshot with a message. You can always go back to it.

Branch

A parallel copy

Try something without touching the version that works. Merge it back when it does.

Push / Pull

Sync

Push sends your save points to GitHub. Pull gets everyone else's.

You'll do all of this from the VS Code sidebar. No terminal, unless you want one.
