Class 2 · Three words

Folder, project, repository.

Three tools, three words, one thing on your disk.

Your computer says

Folder

Files in a directory. What you unzipped. Finder and File Explorer only know this word.

Codex says

Project

A folder Codex has opened. Same files, plus the memory of your threads about them.

Git and GitHub say

Repository

A folder whose history is tracked. Every change recorded, undoable, copyable to GitHub. Yours becomes one next week.

One app · one folder · one project · one repository. Don't rename it, don't move it, don't nest it.

One minute. Land the equivalence: it's the same folder seen by three tools. ZIP = a copy with no history; clone = a copy that stays connected — that's next week. The "don't rename or move" rule is not fussiness: Codex threads and next week's git both point at the folder's address.

Class 2 · Concepts to explore today

Six words.

File

One .py file, one job. app.py screens, logic.py rules, db.py storage.

Function

A named block that does one thing: def add_expense(...). Read the name and the docstring first.

Call

One function using another: logic.add_expense(...) inside app.py.

Table

A CSV file: the first line is the columns, each other line a row.

Entry point

The file that runs first. Here, app.py.

Validation

A check before saving: is_valid_name. Without it, bad data gets in.

Point at one real example of each in the code, 20 seconds each. No definitions beyond this. "Variable" and "loop" come up naturally when they read compute_balances — name them when they ask.
Class 2 · The question every new engineer asks

"Where does X happen?"

Three ways to find out.

1 · Follow the click

Find the button's text in app.py. Read what it calls. Read what that calls. Stop when you reach db.py.

2 · Search

Search the project for the exact words you see on screen. "Find the text 'Add expense' in this project — file and line only." A match, not an opinion.

3 · Ask the AI

Ask Codex to explain, then verify: make it show the line it names, and read it.

Class 2 · Live · Question 4

"Click Add expense. Which function runs?
Which function does that call to save it?"

1Follow the click. Search app.py for "Add expense". It's inside show_expenses. The line under the button calls logic.add_expense(...).
2Follow the call. Open logic.py, find def add_expense. It builds a row and calls db.append_row("expenses", ...).
3Stop at the database. db.py, append_row: opens data/expenses.csv and writes one line. Done.
4Now ask the AI the same question. Did it name the same three functions?

A good answer: "show_expenses (app.py, line 81) → logic.add_expense (logic.py, line 54) → db.append_row (db.py, line 42). Verified by reading the three lines."

Do it exactly in this order, on SplitIt: ask Codex to show each function in turn ("show me show_expenses in app.py", then add_expense, then append_row) so the chain is on screen one link at a time. Then dictate the answer to Codex under Q4 in ONBOARDING.md, read the diff, accept — so they see what "answer with a location" looks like. CRM equivalent: "Move to next stage" → show_stage_buttons (app.py 111) → logic.move_to_next_stage (logic.py 106) → save_lead → db.save_table.

Say where you looked.
