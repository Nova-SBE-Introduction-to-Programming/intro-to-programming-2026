Class 3 · Git, the idea

Git is save points for code.

Repo

The project

A folder git watches. Yours is on your laptop; a copy lives on GitHub.

Commit

A save point

A snapshot of the folder with a message. You can always go back to it.

Branch

A parallel copy

Build on the side. main keeps working while you try.

Push

Upload

Send your commits to GitHub. Until you push, they're only on your laptop.

All of it from GitHub Desktop. Buttons, no terminal.

Analogy that lands: commit = save in a game, branch = a second save slot, push = cloud save. Skip pull, merge conflicts, staging vocabulary. GitHub Desktop ticks every changed file by default — "everything ticked goes in the save".

Class 3 · Your folder becomes a repo · 20 min

Publish to GitHub.

1Install GitHub Desktop from desktop.github.com. Sign in with your GitHub account.
2File → Add local repository → choose last week's folder. It says "not a repository" → Create a repository here.
3Publish repository. Name it splitit or tiny-crm. Leave Keep this code private ticked.
4Repository → View on GitHub. Your files, your fix, online. That was your first commit.

One repo per person. Same folder, same fix, your own copy. Private: only you see it.

Do it on stage first, slowly, then let them go. Two round-trips to the browser (sign in, then View on GitHub) are where people get lost — say out loud "come back to GitHub Desktop". "Create a repository" makes the first commit by itself, with every file in the folder; the `.gitignore` in the ZIP keeps `.venv` and caches out, `data/` goes in, that's fine. If a laptop cloned the org repo in W1 instead of the ZIP, Add local repository finds a remote already: easiest is a fresh ZIP, copy their edits over, then the steps above. No GitHub account: create one now with the university email, two minutes. Windows: GitHub Desktop installs git itself, nothing else needed.

Class 3 · A spec from the PM

What a product manager sends you.

specs/feature-1-balances.md

Why — as a member, I want balances in words I can read out loud.
What — a checklist. balance_lines(group_id), one sentence per member, "João is owed €20.00".
Out of scope — settle up, rounding, storage.
Done when — tests green · visible on the page · on a branch, pushed.

Read it as an engineer

Which file changes? logic.py and app.py.
What do I reuse? compute_balances, get_group_members.
What's ambiguous? Ask, or read the test.

The spec is also your prompt. Paste it to Codex as is.

Open the real file on screen and read the What checklist aloud. Point at "Blocked by issue 001" at the top: they fixed that last week, so they're unblocked. CRM feature 1 is blocked by their bug 002 (dates compared as text), which they have not fixed. Say so: CRM groups fix 002 first, and their feature will spill into next week. That's fine.
Class 3 · Tests

Tests are the spec, in code.

What a test is

A tiny program that calls your function and checks the answer. Green = matches. Red = doesn't.

Why you care

You didn't write most of your code. Tests tell you whether the AI did what you asked.

The loop

Red → build → run → still red? Read the failure. → green. Then click through the app anyway.

uv run pytest tests/test_feature_1.py — four tests, one per line of the spec's checklist.

Run it before building: 4 red, "balance_lines does not exist". Open the test file and match each test to a checklist line: one line per member / is owed / owes / settled up. Read one assertion aloud: "the test expects the string João is owed €20.00 to be in the list".
Class 3 · Live · Feature 1

Branch → build → green → merge.

1Branch. GitHub Desktop → Current branch → New branch → feature-1-balances.
2Red. uv run pytest tests/test_feature_1.py. Four failures. That's the to-do list.
3Prompt. Paste the spec and the test file into Codex. Ask for balance_lines in logic.py.
4Read the diff in GitHub Desktop. Does it reuse compute_balances? Two decimals? No minus sign?
5Green. Run the tests. Then show_balances in app.py prints the lines. Refresh, look.
6Commit, push, Create Pull Request, merge. One button each. Then switch back to main and Pull origin.
Narrate every decision; this is what they copy. Let Codex get one thing wrong and show it in the tests (a common miss: "€8.2" instead of "€8.20", or the minus sign kept). Fix by hand or re-prompt, run again. After push, GitHub Desktop offers Create Pull Request; it opens GitHub, show the diff, merge there. Back in GitHub Desktop: Current branch → main, Pull origin, the feature is there. If time is short, skip the PR and merge on GitHub straight from the branch page.

Class 3 · When git is confusing

You can't lose a commit.

1Wrong branch? Current branch → switch. GitHub Desktop asks to bring your changes along. Say yes.
2Broke a file? GitHub Desktop → right-click the file → Discard changes. Back to the last commit.
3Broke the data? uv run python seed.py, same as last week.
4An error you don't understand? Screenshot it, ask Codex to explain it, then ask us.
